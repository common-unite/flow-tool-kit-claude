# Before drawing

Moved from this skill's SKILL.md, read on demand: Before drawing.

## Before drawing

1. **The project config.** Read `flow-tool-kit.json` at the project root (in chat: among the conversation's or the claude.ai Project's files). It holds the link to the person's own **FlowToolKit Forms** design system (`design_systems.forms.url`), the org's edition (paid or free) and the org catalog's file. No design system link: tell the person to run **ftk-start**'s design system step, which installs their own copy from the plugin's files and saves the link. Never use a design system from anyone else's account. You can still write and check `plan.json` meanwhile.
2. **The org catalog.** org-catalog's file lists the org's Form Components, Form Templates and the sections that repeat. No catalog (no org connected): say so in one line, mark every component `reason: "no catalog"` and list that in the plan's `questions`.
3. **The source.** form-migrate's `ir.json` (questions, choices, rules, coverage), or brief mode's. Keep its source ids.
4. **The design system README.** In Claude Code read the person's design system (`project/README.md` of the artifact in the config); in chat read `_shared/design-systems/ftk-forms/project/README.md`. It names every component and variant exactly as stored; a name it does not list cannot be built. The header, background and people photos packaged with Flow Tool Kit are listed by Content Asset name in `_shared/design-systems/images.json`, with thumbnails in `_shared/design-systems/images.html`.
5. **The rules.** `_shared/standards/form-type-rules.md` and `_shared/standards/form-house-rules.md` (until the shared copies exist: [references/form-type-rules.md](form-type-rules.md) and [references/house-rules.md](house-rules.md)), `_shared/standards/mapping-preference.md` and `_shared/standards/documentation.md`.
6. **The brand**, only if the person chose one in ftk-start: the saved brand kit (colors, fonts, logo, banner, tone, the program page's words). No brand kit is fine: the plan's `style` falls back to a neutral palette and the package banner photo.
7. **The gap interview**, one short round, before drawing. A source or a brief rarely says everything a complete Form Template needs. Check the list below against the source, the brief, the org catalog, the brand kit and the project config, and ask **only** what none of them answers: every missing item at once, numbered, each with a sensible default stated so the person can answer "yes to all". Skip the round when nothing is missing, and never ask it twice: when ftk-start already ran it, use the answers already in the plan's `intake`.
   - **Confirmation message**: the general idea (what happens next, by when, who to contact) and the tone. Default: thanks, why it matters and the next step, in the brand kit's tone or warm and plain.
   - **Emails**: whether the respondent gets a confirmation email (default: yes when the form collects an email), who it comes from and who replies go to (default: the org's usual sender; name an org-wide address if they have one), and whether staff are told when a submission arrives and who (default: no staff notice; recommend a shared inbox if they want one).
   - **Save Progress and the resume link**: on or off. Default: the form-type row's setting (on for a long form, off for a short one).
   - **The program**: "What program is this form for?", with the program page's address if they have one. brand-kit then writes that program's voice (its own names, phrasing and sample copy) for the page descriptions, blurbs, question labels, help text and confirmation. Default: the organization's general voice.
   - **Build mode**: "Build as metadata, or load as records for fast prototyping?" Records mode builds the template and its new or extended components as records and JSON only, with no metadata deploy, so it runs from claude.ai chat with a Salesforce connector; good for quick design, review and changes, and convert-to-metadata turns it into metadata when the prototype is final. Metadata mode deploys through Claude Code. Default: records in chat, metadata in Claude Code.
   - **Header, banner and logo**: which logo and banner image. Default: the brand kit's; without a kit, no logo and the package banner photo.
   - **Who reviews submissions**, for an internal audience: a person, a team or a queue. Default: none named; the build leaves the review step to the org's own process.
   - **Anything else the build needs that the source did not give**: for example who to contact on the closed-form message, whether a fee applies, or who owns consent wording. Each with its default.
   Record the answers and the defaults taken in the plan's `intake.gap`, the program in `intake.program` and the build mode in `intake.build_mode` (references/plan-format.md), and each choice in `decisions`. A default taken is a decision too: say so in the plan, so the review can change it.
